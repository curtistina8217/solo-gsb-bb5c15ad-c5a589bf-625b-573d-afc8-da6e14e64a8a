# 文稿批注迁移工具

供校对人员使用的单机网页工具：在旧版文稿上框选文字写批注，粘贴新版文稿后，系统根据**选中文本 + 前后文**在新稿中自动重新定位批注；无法可靠定位时一律标为「待处理」交给人工，**绝不静默挂到错误段落**。

技术栈：Node.js + Express + 原生前端（无构建步骤），数据以 JSON 文件保存在本机 `data/` 目录。

## 快速开始

### 方式一：Docker（推荐，一条命令）

```bash
docker compose up --build
```

### 方式二：本机 Node.js（≥ 18）

```bash
npm install && npm start
```

### 访问地址

启动后在浏览器打开：**http://localhost:3000**

- 默认端口：`3000`。本机方式可用 `PORT=8080 npm start` 修改；Docker 方式修改 `docker-compose.yml` 中的 `ports` 映射（如 `"8080:3000"`）。
- 数据目录：`./data/documents/*.json`（每份文稿一个文件，Compose 已挂载到容器 `/app/data`，删除容器不丢数据）。

## 使用流程

1. **新建文稿**，在 ① 中粘贴旧版文稿并保存；
2. 在旧稿阅读区**框选文字**，弹出输入框写下批注（可反复添加多条）；
3. 在 ② 中粘贴新版文稿，点击「保存新稿并迁移批注」；
4. 在 ③ 中并排查看：左侧为新稿（高亮定位结果），右侧为每条批注的状态：
   - 🟢 **已定位**：唯一出现，或重复出现但前后文可明确区分；
   - 🟡 **待处理**：原文已删除/改写（附相似片段候选），或多处出现且前后文并列（附全部候选位置）——点击候选即可采用；
   - 🔵 **人工指定**：点击「手动定位」后在左侧新稿中框选文字，即保存为该批注的位置（任何批注都可用此方式修正）。
5. **重叠复核**：迁移或人工定位后，系统自动把新稿中位置重叠的批注归入冲突组（见下节），在 ③ 顶部逐条列出；
6. 所有操作即时保存，无需额外动作；可随时修改新稿后「重新迁移」。

## 新稿批注重叠复核

每次**迁移**或**人工定位**（采用候选 / 手动框选 / 修改任一位置）后，对已有确定位置的批注即时重算重叠分组：

- **判定方式**：位置按**半开区间 `[start, end)`** 判定，两条批注满足 `a.start < b.end && b.start < a.end` 才算重叠；**端点相接**（前一条的结尾正好是后一条的开头）**不算重叠**。
- **入组范围**：只有「已定位（🟢 matched）」和「人工指定（🔵 manual）」等**已有确定位置**的批注参与；**待处理**与**未迁移**批注没有确定位置，**不入组**。
- **传递性**：重叠关系按传递闭包合并（并查集）——A 与 B 交叠、B 与 C 交叠，即使 A、C 互不相交，三条也属于同一冲突组。
- **组类型**：
  - **完全相同（exact）**：组内全部批注的新稿范围端点完全一致；
  - **部分交叠（partial）**：组内存在只重叠一部分的范围，面板会标注每条批注各自的范围。

结果页 ③ 顶部的「新稿批注重叠复核」面板列出每组的**全部批注与对应范围**（原文、批语、状态、`[起, 止) · 字数`）及合并范围的新稿内容预览；点击「跳转到新稿位置」可定位到该组/该批注在新稿中的高亮处。右侧批注卡片上也有冲突标签，点击同样可跳转。**修改任一位置后分组即时重算**（重新迁移、采用候选、手动框选均会触发）。

**重叠处的高亮不会互相覆盖**：重叠区间渲染为嵌套高亮（颜色叠加、虚线描边），范围内的**每条批注都能被查看和选中，不会跳过后续批注**——点击重叠位置会弹出该处全部批注的列表，点选其一即可定位到对应卡片；非重叠位置单击即直接选中。

## 定位规则（核心保证）

| 情况 | 结果 |
|---|---|
| 选中文本在新稿出现 1 次 | 自动定位 |
| 出现多次，比较前后各 80 字符上下文，最高分领先次高分 ≥ 0.3（满分 2） | 自动定位到最高分 |
| 出现多次但上下文得分并列 / 无上下文依据 | **待处理**，列出全部候选位置 |
| 出现 0 次（删除或改写） | **待处理**，附二元组相似度 ≥ 0.45 的相似片段候选 |

匹配对换行、多余空格等空白差异不敏感（归一化后比对，位置映射回原文）。

迁移与人工定位只负责给出每条批注的新稿位置；**批注之间的重叠不在迁移阶段自动消解**，而是交由「新稿批注重叠复核」分组呈现（半开区间、传递成组，规则见上节）。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/documents` | 文稿列表 |
| POST | `/api/documents` | 新建文稿 `{title}` |
| GET / DELETE | `/api/documents/:id` | 详情 / 删除 |
| PUT | `/api/documents/:id/old` | 保存旧稿 `{oldText}`（自动重算批注上下文） |
| POST | `/api/documents/:id/annotations` | 添加批注 `{start, end, comment}` |
| DELETE | `/api/documents/:id/annotations/:aid` | 删除批注 |
| PUT | `/api/documents/:id/new` | 保存新稿 `{newText}` |
| POST | `/api/documents/:id/migrate` | 执行迁移 |
| PUT | `/api/documents/:id/annotations/:aid/position` | 人工指定位置 `{start, end}`（与迁移后均即时重算重叠分组） |

重叠分组在前端复用共享模块 `lib/overlap.js` 即时计算（同时由单元测试覆盖，浏览器经 `GET /lib/overlap.js` 加载同一份代码），无需单独的 API。

## 项目结构

```
server.js          Express 服务与 API
lib/match.js       批注重定位核心算法
lib/overlap.js     新稿批注重叠分组（半开区间/传递成组，前后端共享）
public/            原生前端（index.html / app.js / style.css）
test/match.test.js   定位算法单元测试
test/overlap.test.js 重叠分组单元测试
data/              文稿与批注数据（运行时生成）
Dockerfile / docker-compose.yml
```
